# Product Spec: 角色管理模块

**Issue:** #13
**Status:** Draft

Figma: none provided

---

## 1. 概述

实现角色管理模块的完整 CRUD 功能，包括角色的新增、修改、删除、单个查询和分页查询。删除角色时需要检查是否有用户关联，有关联时阻止删除。

## 2. 问题

当前系统中角色（SysRole）实体已存在，但没有任何 API 接口对其进行管理。系统运维需要通过 API 对角色的增删改查进行管理。

## 3. 目标

1. 提供角色 CRUD 的全部 API 接口
2. 新增角色时，角色名称和编码不能为空
3. 删除角色时，校验是否有用户关联了该角色，有关联则阻止删除
4. 分页查询支持按角色名称或编码搜索
5. 响应遵循统一 `ApiResponse<T>` 格式

## 4. 非目标

- 不实现角色与用户的关联关系维护（关联数据由其他模块管理）
- 不实现角色权限控制（仅管理角色本身）
- 不实现批量操作

## 5. 用户体验

### API 接口

#### POST /role
创建角色。

**请求体：**
```json
{
  "name": "管理员",
  "code": "admin",
  "description": "系统管理员角色",
  "sortOrder": 1
}
```

**验证规则：**
- name: 必填，最长 50 字符
- code: 必填，最长 50 字符，字母数字组合
- description: 可选，最长 200 字符
- sortOrder: 可选，默认 0

**响应：** `ApiResponse<SysRole>` — 返回创建后的角色对象

#### DELETE /role/{id}
删除角色。

**行为规则：**
- 如果角色已被用户关联，返回 400 及错误信息 "该角色下存在用户，无法删除"
- 系统内置角色（isSystem=true）不能删除，返回 400 及错误信息 "系统内置角色不能删除"
- 正常删除返回 `ApiResponse<bool>`

#### PUT /role/{id}
更新角色。

**请求体：** 同创建

**响应：** `ApiResponse<bool>`

#### GET /role/{id}
获取单个角色详情。

**响应：** `ApiResponse<SysRole>`

#### GET /role/list
分页查询角色列表。

**参数：**
| 名称 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| pageIndex | int | 否 | 1 | 页码 |
| pageSize | int | 否 | 10 | 每页条数 |
| keyword | string | 否 | null | 搜索关键词（匹配角色名称或编码）|

**响应：** `ApiResponse<PageModel<SysRole>>`

## 6. 成功标准

1. 创建角色：发送合法数据，返回 200 且包含新角色的 ID
2. 创建角色（名称为空）：返回 400 验证错误
3. 查询角色：通过 ID 获取，返回角色详细数据
4. 更新角色：修改名称后查询确认已更新
5. 删除角色（无关联）：正常删除，返回 success: true
6. 删除角色（有用户关联）：返回 400 及错误提示
7. 删除系统内置角色：返回 400 及错误提示
8. 分页查询：返回正确的分页数据
9. 关键词搜索：返回匹配的结果

## 7. 验证

1. 使用 curl 测试每个接口的合法请求
2. 验证错误场景：空名称、空编码、删除关联角色等
3. 分页测试：不同 pageIndex/pageSize 组合

## 8. 开放问题

- 角色与用户的关联关系表在哪里？删除检查时需要通过关联表查询。当前假设通过角色 ID 在用户表中查询（SysUser 表有 roleId 字段，或在独立的关联表中）。
